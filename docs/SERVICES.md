# Nightfall: services and operations

What runs the game, where its settings live, and what to do when something
breaks. Secret values (connection strings, tokens, passwords) are **never**
written here or anywhere in the repository. This file only says where they are.

Last reviewed: 2026-10-27.

```
 players' browsers ──HTTPS / WebSocket──▶ Render (Node server, in-memory game state)
                                              │  writes within seconds, loads on start

```

## Render: the game server

- **Service:** `nightfall`, a Node web service created from `render.yaml`.
- **Region:** Oregon (Render's default, since `render.yaml` sets none).
- **Deploys:** automatic on every push or merge to `main`. Build `npm ci --omit=dev`, start `npm start`, health check `/healthz`.
- **Free plan behaviour:**
  - The server sleeps after 15 minutes with no visitors. The next visitor waits 30 to 50 seconds. UptimeRobot prevents this.
  - 750 free instance hours per month, enough for one service running nonstop.
  - The disk is wiped on every deploy and restart. That is why all data lives in Neon.
- **Logs:** service → **Logs**. A healthy start shows:
  ```
  [db] connected, tables ready
  [store] using the database: N profiles, N scores
  [analytics] using the database: N recent events loaded
  Nightfall is listening on ... (storage: database)
  ```

### Environment variables (service → Environment)

| Name | Purpose | Notes |
|---|---|---|
| `DATABASE_URL` | Neon connection string | Secret. Prefer Neon's **direct** string (host without `-pooler`). |
| `DATABASE_URL_POOLED` | Neon pooled connection string | Secret. **Not used by the game**; kept for reference. Safe to delete. |
| `ADMIN_TOKEN` | Unlocks the private stats page | Secret, generated by Render. Stats: `https://nightfall-cps8.onrender.com/admin/stats?token=<ADMIN_TOKEN>` |
| `DATA_DIR` | Local folder for fallback files | Only used if the database is unreachable at startup |
| `NODE_ENV` | `production` | |
| `PORT` | Set by Render | Do not set by hand |

## Neon: the database

- **Project:** `Nightfall`, Postgres, default branch and database.
- **Region:** chosen at creation. The recommended region is AWS `us-west-2` (Oregon), next to Render. Check it under project settings and note it here: `____________`.
- **Tables:** created automatically by the server on first start.

  | Table | Contents |
  |---|---|
  | `nf_kv` | The score boards (all-time Hall of the Survived and the daily Tonight's Night boards) as one JSON document |
  | `nf_profiles` | One row per player name: unlocked nights, relics, wins, survivor skin, salted hash of the recovery code |
  | `nf_events` | Anonymous analytics events (random device id, no names). Pruned automatically after 60 days |
- **Free plan limits (as of October 2026; check [Neon pricing](https://neon.com/pricing)):**
  - 0.5 GB storage. Scores and profiles are tiny; analytics is the only thing that grows, and it is pruned.
  - 100 compute-hours per month. Compute sleeps after a few minutes with no queries and wakes on the next one in about a second. The game only queries when something changes, so a quiet game uses very little.
  - If the hours run out, Neon suspends compute until the month resets. The game keeps running, but changes cannot be saved and are lost on the next restart. Watch usage in the Neon console; the paid plan removes the limit.
- **Credentials:** the connection string lives only in Render's environment. To rotate it: reset the role's password in Neon (Roles), copy the new connection string, replace `DATABASE_URL` in Render, and save. Render redeploys.
- **Restore:** Neon keeps a short history for point-in-time restore. The free plan's window is small, so check it in the console before relying on it.

## UptimeRobot: keep-alive

- **Monitor:** type HTTP(s), URL `https://nightfall-cps8.onrender.com/healthz`, interval 5 minutes (the free minimum).
- **Why:** Render's free server sleeps after 15 minutes without traffic. A request every 5 minutes keeps it awake, so shared links open instantly.
- **Cost to other limits:** `/healthz` answers "ok" without touching the database, so it does not use Neon compute hours. Running nonstop uses about 720 of Render's 750 free hours a month.
- **Alerts:** set the monitor to email the owner when the site goes down. This doubles as free uptime monitoring.

## GitHub: code and deploys

- Work happens on branches and is merged to `main` through pull requests. Every merge to `main` deploys to Render automatically.
- `render.yaml` describes the Render service. `README.md` covers development; this file covers operations.
- Never commit `.env` files, connection strings or tokens. `data/*.json` is ignored by git.

## Runbook

| Symptom | Likely cause | What to do |
|---|---|---|
| Site takes 30 to 50 s to open | Render was asleep | Check that the UptimeRobot monitor is active and green |
| Site down, UptimeRobot alert | Crash or failed deploy | Render → Logs. If a deploy broke it, Render → Events → roll back to the previous deploy |
| Log says `storage: files` and "database is unreachable" | Neon down, suspended or wrong `DATABASE_URL` | Check the Neon console (compute status, monthly hours). Fix the variable, then Render → Manual Deploy. Data saved while on files is **not** copied to the database later |
| Log says `database write failed, will retry` | Short Neon outage | Usually recovers by itself. If it persists, check Neon's compute status and hours |
| Players lost names or relics after a deploy | `DATABASE_URL` missing or emptied | Restore the variable in Render; the data is still in Neon |
| Stats page says 403 | Wrong token in the URL | Copy `ADMIN_TOKEN` again from Render → Environment |
| Stats page says "disabled" | `ADMIN_TOKEN` not set | Add it in Render → Environment |

## Costs and upgrade paths

Everything above is free today. Upgrade when there is a reason:

- **Render Starter** (paid): no sleeping, so UptimeRobot becomes optional; faster CPU for more simultaneous rooms.
- **Neon Launch** (paid): removes the compute-hour cap and adds storage and longer restore history.
- **UptimeRobot Pro** (paid): 1-minute checks and status pages. Not needed for keep-alive.
